# PRODUCT.md — TeachOnce 产品定位与方向

> **本文件是产品方向的唯一基准。任何开发前先读本文件，任何产品行为变更同步更新本文件。**
> 最后更新：2026-10-14（调优/评估案例隔离、优化来源继承和严格裁判校验）

## 1. 一句话定位

**TeachOnce：Teach your AI once. Let it learn how you work.**
一个从用户实际操作、任务示范和纠错反馈中持续学习「个人工作经验」的引擎，以 **Agent Skill + MCP Server** 形态存在。

## 2. 项目形态（不可漂移）

- ✅ Agent Skill + MCP Server。
- ❌ 不是独立桌面 AI 应用；❌ 不是通用 AI Agent；❌ 不是通用 RPA / 工作流录制工具。
- 核心能力不要求用户安装新的通用 Agent——TeachOnce 依附于用户已有的 Agent 提供经验层。

## 3. 目标使用体验（愿景闭环）

1. 用户亲自完成一次任务，AI 观察并学习。
2. AI 提取 SOP，形成可复用的 Skill。
3. 遇到类似任务，AI 自动判断是否适用并尝试接手。
4. 用户发现错误后，通过自然语言纠正 AI。
5. AI 将纠错转化为可复用的经验，持续优化原有 Skill。
6. 面对没有示范过的新情况，AI 利用已学到的判断规则灵活处理。
7. 个人积累的 Skill 可以在不同 Agent 中复用。

> MVP 阶段第 1 步采用**结构化示范导入**（JSON/Agent 任务记录/自然语言描述），
> 屏幕 GUI 观察（第 1 步的完全体）属于计划中能力，需用户显式授权后另行实现。

## 4. 真正的创新点（与普通录制工具的区别）

### 4.1 学习个人决策经验
普通录制只知道**做了什么**；TeachOnce 学习**为什么这样做**、什么情况下换个做法、异常如何处理。
从多个实际任务中提取**可迁移**的经验，而不是把操作机械固化为固定流程。

### 4.2 跨任务经验迁移
遇到没有演示过但特征相似的任务，能利用已学到的决策规则作出**正确判断**（而非匹配失败）。

### 4.3 持续自进化
根据纠错、执行失败和反馈持续更新 Skill：
- 不仅是修复当前错误，还要沉淀为对未来任务通用的经验；
- 更新必须**可解释**（结构化变更说明）、**可验证**（未见案例回归评估）、**可撤销**（版本回滚）；
- **绝不允许**把未经确认的错误经验直接固化为规则。
- 多轮修订保留规则 ID 和累计纠错来源；纠错仅用于所属 Skill，已应用反馈不会被重复消费。
- 新版本和纠错状态在同一事务中保存，并发或写入失败时保持一致；候选版仍需人工审批。
- **GEPA 反思进化**（可选能力）：用调优案例驱动规则自动优化（`teachonce_optimize_skill`）。
  优化预算显式受控；产物是 **candidate**，与纠错修订一样必须人工审批 + 回归评估后才能生效——
  自动优化永远不直接改变 active 版本。案例一旦用于优化即成为学习输入，优化分数不能
  作为未见案例成绩；必须另备独立评估集。历史手工记录（DeepSeek，预算 10 次，非本次复测）
  中的 0/4 → 2/4 属于调优案例反馈，**不是独立泛化评测或产品效果宣称**。
  新优化版本持久化规范化情境指纹，多轮优化与纠错继承累计指纹及优化来源。

### 4.4 主动识别与接手
识别当前任务与个人 Skill 的匹配关系，在合理权限内使用经验；**不匹配或高风险任务向用户确认**，不硬套旧流程。

### 4.5 跨 Agent 使用
通过 Agent Skills 标准导出 + MCP 接口，让教给一个 Agent 的经验被其他兼容 Agent 复用，减少重复教学。

## 5. 开源复用策略（评估清单）

原则：**不重复造轮子；使用前核查 API / 维护状态 / 许可证（须与 MIT 兼容）/ 技术适配成本；优先适配器接入，避免深度耦合。**

| 项目 | 拟复用的能力 | 状态（2026-10-14） | 备注 |
|---|---|---|---|
| GEPA（gepa-ai/gepa） | 决策规则反思进化（自进化引擎） | ✅ 已集成 | `adapters/gepa_optimizer.py`，`optimize_anything` + 自有 LLM 判分；产物恒为 candidate，需人工审批；可选依赖 `teachonce[gepa]` |
| OpenAdapt / openadapt-capture | GUI 操作观察、示范记录 | 🔶 部分集成 | 录制导出 JSON → Demonstration 导入已实现（`adapters/openadapt.py`），需 `TEACHCONE_GUI_OBSERVATION=1` 显式授权；录制由 openadapt-capture CLI 完成，实时观察未集成 |
| Hermes Agent（NousResearch） | Skill 创建/更新/经验持久化 | ⛔ 评估完成：不集成 | 其自进化核心即 DSPy+GEPA 优化 SKILL.md——已被 GEPA 直接集成覆盖（更底层、不耦合其仓库）；Skill 格式互操作由 Agent Skills 标准满足 |
| Hermes Agent Self-Evolution | Skill 优化与评测 | ⛔ 评估完成：不集成 | 同上；其"进化产物走 PR 人工审查"原则已被我们的 candidate→审批门采纳 |

| Agent Skills 标准 | Skill 可移植格式 | ✅ 已采用 | `skill_export.py` 输出标准 `SKILL.md` |
| MCP Python SDK | 标准 MCP 接口 | ✅ 已采用 | v2 `MCPServer`（原 `FastMCP`），`mcp_server.py` |

**自主开发（不外包的核心）**：个人经验学习（`learning.py`）、决策规则迁移（`matching.py`）、持续改进（`correction.py` + `evaluation.py`）。

## 6. MVP 目标与验收标准

### 6.1 MVP 流程（7 步，全部必须真实可跑）

1. 导入一次任务示范：记录任务目标、操作、关键判断、结果。
2. 结合后续示范或纠错，生成含**适用条件 / 决策规则 / 异常处理**的 Skill。
3. 为新任务选择合适的 Skill，并**说明匹配原因**。
4. 调用现有 Agent 工具或适配器完成新任务（MVP：输出判断与行动计划，供宿主 Agent 执行）。
5. 人类纠错后生成**改进版 Skill**，保留历史版本。
6. 通过**未见过的案例**验证新版本比旧版本更可靠。
7. 通过 **MCP** 暴露学习、匹配、执行准备、更新能力。

已实现的历史恢复：通过 MCP 查询已保存的示范、待处理 / 已应用纠错和完整评估报告。
新聊天或服务重启后使用同一数据库即可继续学习；这些查询不需要 LLM，也不会触发重新评估。

### 6.2 首个 Demo 场景：「个人文件与课程资料整理」

演示叙事：**人类教 AI 几次 → AI 学会处理原则 → 遇到新的文件组织问题仍能正确判断 → 用户纠正后下一次处理得更好。**

### 6.3 成功标准（防自欺）

- ❌ 不是「生成了一个 SKILL.md」。
- ✅ 是「从未见过的案例上，AI 能依据学到的决策规则给出正确判断；纠错后 v2 在回归集上不劣于 v1 且修复了被纠错的问题」。
- 评估与优化输入在调用模型前整批校验并扫描敏感信息；批内重复情境拒绝处理。
  二者裁判的通过 / 不通过结果必须是 JSON 布尔值，预测和理由必须是非空字符串；异常输出不计分、不落库。
- 报告始终携带所用方法的局限（包括用户补充备注时）。当前 LLM 裁判属于规则支持性判断，
  不是独立的真实执行成功率测试。系统会检查评估案例与两个版本已记录 GEPA 调优案例的
  规范化情境指纹是否重叠，改变期望答案或案例 ID 不能绕过检查，重启后仍有效。
  尚不能识别同义改写、示范/纠错的语义重叠，旧优化版本可能缺少指纹；未见案例仍须
  由调用者独立准备。报告始终包含这些检查局限，不能把“未发现重叠”说成已证明独立。

## 7. 安全与隐私承诺（产品级）

- 不记录或公开真实密码、Token、Cookie 等敏感信息（导入时红灯拦截）。
- GUI 操作记录需用户明确授权，属计划中能力。
- 不自动执行未授权的危险文件操作（TeachOnce 自身不写用户文件系统）。
- Skill 更新提供变更说明，支持人工审批和回滚。
- 个人操作记录默认本地保存（`~/.teachonce/`），不默认公开。
- 所有能力必须真实实现，不允许硬编码输出伪装成功；文档严格区分已实现与计划。

## 8. 术语表

| 术语 | 含义 |
|---|---|
| Demonstration（示范） | 一次任务的结构化记录：目标、步骤、关键判断、结果 |
| Skill | 从示范中提取的可复用工作经验：适用条件 + 决策规则 + 异常处理 + 反面模式 |
| SkillVersion（版本） | Skill 的一次修订，append-only 保存；状态：candidate / approved / rolled_back |
| DecisionRule（决策规则） | 「在什么条件（condition）下 → 怎么做（decision）→ 为什么（rationale）」 |
| Correction（纠错） | 用户对 AI 判断的自然语言纠正，可转化为新版本 |
| Held-out cases（未见案例） | 未参与学习的评估案例集，用于版本对比 |
| Match（匹配） | 新任务与 Skill 的适用性判断：含置信度、理由、是否需人工确认 |

## 9. 反目标（明确不做）

- 不做「一次录制、永久回放」的宏工具。
- 不做黑盒自动修改 Skill：所有规则变更可读、可审、可回滚。
- 不做云端账户体系（MVP 阶段）；不收集用户数据。
- 不以降低诚实性为代价美化 demo（虚构成功率、演示数据造假均为红线）。

# 0.4 试用验收与后续质量门槛

状态：**受控试用候选版**。项目定位仍是 Agent Skill + MCP Server。
以下是可检查的交付标准，不把测试数量当作模型效果，也不以“功能多”定义完整。

## 已有工程证据

| 验收项 | 实现与验证 |
|---|---|
| 新机器可安装 | wheel 包含 CLI、交互 Demo、情境输入和 TeachOnce Skill；独立安装冒烟检查 |
| Codex 可接入 | 生成真实 Python 路径的配置、凭据变量转发、审批工具 prompt 策略；真实 stdio 启动和重启恢复测试 |
| 低接入成本 | 明确宿主提案路径无需另一套模型 Key，标记来源；API Provider 仍可选 |
| 学习与持续纠错 | 示范与反馈恢复、候选版本、证据来源、累计优化指纹、实际字段差异 |
| 审批可靠 | 绑定当前基准和已保存报告、候选逐例通过、显式用户确认；原子更新与持久审计；并发/写入失败回归 |
| 可撤销 | 既有批准版本可恢复，包含再次启用曾 rolled_back 的版本 |
| 评估诚实 | 默认盲决策后比较；旧规则支持性裁判和启发式明确标注；案例隔离不承诺语义去重 |
| 执行反馈闭环 | 宿主上报结果、可恢复查询、显式反馈成为 open correction；不自动固化错误经验 |
| 数据边界 | 结构化凭据扫描、无原始远程错误内容回显、严格数字与 JSON、HTTPS 远程端点；非万能秘密检测 |
| 跨 Agent 输出 | YAML 安全引用、合法 slug、候选警告、版本所属校验；标准 SKILL.md |

测试只使用 ScriptedLLM、测试提案和测试优化器；真实 stdio 测试调用真正的 SDK/子进程。
CI 设计覆盖 Linux/Windows、Python 3.12/3.13，并在仓库之外安装 wheel 验证资源与命令。

## 必须继续收集的产品证据

- 在实际 Codex 聊天中完成一次本人示范、迁移、执行、纠错、再次迁移，由用户确认是否符合习惯。
- 使用独立准备的中文/英文课程资料案例验证冲突、例外、新课程、历史版本、未知归属与失败处理。
- 记录真实判断与执行结果，区分计划正确、工具执行正确、用户最终接受；报告失败，不只展示成功案例。
- 让不同用户及另一个兼容 Agent 复用导出的 Skill，记录安装、解释、权限和规则迁移问题。

这些尚不是本轮离线测试所证明的能力；没有真实运行数据时不得宣称生产成功率或“优秀完成”。
实时 GUI 观察、开放领域泛化、语义级训练/测试去重、多用户身份验证仍不在已交付范围。

## 兼容性与维护

0.4 新增审批参数和逐例评估约束，旧的无条件 approve 调用会明确报错。
`auto` 在有 API Provider 时改为 llm_blind，模型调用数随之增加；旧 llm_judge 可显式选择。
新表只通过 CREATE TABLE IF NOT EXISTS 添加，保留已有数据。历史批准版本继续可用，
但旧版本缺失的审计事件或调优指纹不能凭空补齐。升级前可备份个人数据库。

每次迭代仍先读 AGENTS.md 和 PRODUCT.md；独立分支、真实验证、PR 审阅后再发布，
不自动合并 main，不自动把用户记录上传到公开仓库。
